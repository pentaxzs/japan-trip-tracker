# 서비스 기획서: 일본여행 TODO 기록앱 (Japan Trip Tracker)

---

## 1. 개요

| 항목 | 내용 |
|------|------|
| 서비스명 | Japan Trip Tracker |
| 한 줄 소개 | 여행 전 · 중 · 후 3단계로 나눠 일본 여행을 완벽하게 정리하는 TODO 웹앱 |
| 핵심 가치 제안 | 일본 여행의 설렘부터 마무리까지, 한 앱에서 단계별로 체계적으로 기록 |
| 타겟 사용자 | 일본 여행을 준비하거나 진행 중인 한국인 여행자 |
| 기술 스택 | Next.js (SPA), LocalStorage, Tailwind CSS |
| 배포 형태 | 단일 페이지 웹앱 (백엔드 없음) |

---

## 2. 문제 정의

### 현재 문제점

- 여행 준비 시 메모앱, 메신저 즐겨찾기, 종이 메모 등 도구가 분산되어 관리가 어렵다.
- 여행 전 / 중 / 후 할 일이 성격이 완전히 다름에도 하나의 리스트에 뒤섞인다.
- 일본 여행 특화 TODO 템플릿(여권, 엔화, 스이카 충전 등)이 존재하지 않는다.
- 여행 후 정산 · 후기 작성 등 마무리 단계는 별도 앱에서 처리해야 한다.

### 해결 방향

- 여행의 3단계(전/중/후)를 명확히 분리한 TODO 관리 구조 제공
- 각 단계별 분위기에 맞는 디자인으로 사용자 감성 경험 극대화
- 일본 여행에 최적화된 기본 TODO 템플릿 제공으로 진입 장벽 최소화
- 로컬 스토리지 기반으로 로그인 없이 즉시 사용 가능

## 3. 타겟 사용자 페르소나

### Persona A — "첫 일본 여행 준비생" 지수 (25세, 직장인)

- **상황**: 처음으로 일본 여행을 계획 중이며 무엇을 준비해야 할지 막막함
- **목표**: 빠짐없이 준비하고 여행 중에도 할 일을 놓치지 않고 싶음
- **Pain Point**: 네이버 메모 / 카카오톡 나에게 보내기로 관리하다 분실 경험 있음
- **기대**: 체크리스트 형식으로 무엇을 했고 안 했는지 한눈에 파악하고 싶음

### Persona B — "일본 단골 여행자" 민준 (32세, 프리랜서)

- **상황**: 연 2~3회 일본을 방문하며 매번 비슷한 준비를 반복함
- **목표**: 이전 여행 패턴을 재활용해 준비 시간을 단축하고 싶음
- **Pain Point**: 맛집, 쇼핑 리스트가 SNS 저장 폴더에 흩어져 여행 중 찾기 불편함
- **기대**: 여행별로 리스트를 관리하고 완료된 항목을 한눈에 확인하고 싶음

## 4. 핵심 기능 명세

### 4.1 Must-have (MVP — Phase 1)

#### M-01: 3단계 모드 전환

- **User Story**: 사용자로서, 여행 전/중/후 탭을 클릭해 단계를 전환하고 싶다. 각 단계에 맞는 할 일만 보기 위해.
- **수용 기준**:
  - 화면 상단에 "여행 전 / 여행 중 / 여행 후" 탭이 항상 표시된다.
  - 탭 클릭 시 해당 단계의 TODO 리스트만 렌더링된다.
  - 현재 활성 탭은 시각적으로 강조 표시된다.
  - 탭 전환 시 페이지 이동 없이 콘텐츠만 교체된다 (SPA).

#### M-02: TODO 항목 추가

- **User Story**: 사용자로서, 각 단계에서 새 TODO 항목을 추가하고 싶다. 해야 할 일을 빠짐없이 기록하기 위해.
- **수용 기준**:
  - 텍스트 입력창에 내용을 입력 후 Enter 키 또는 추가 버튼으로 저장된다.
  - 빈 입력값은 추가되지 않는다.
  - 추가 즉시 리스트에 표시된다.
  - 항목은 현재 활성 단계에만 저장된다.

#### M-03: TODO 항목 완료 체크

- **User Story**: 사용자로서, 완료한 항목에 체크 표시를 하고 싶다. 무엇을 했고 남은 게 무엇인지 파악하기 위해.
- **수용 기준**:
  - 각 항목 좌측에 체크박스가 표시된다.
  - 체크 시 항목에 취소선 및 완료 스타일이 적용된다.
  - 재클릭 시 체크가 해제된다.
  - 완료/미완료 상태가 LocalStorage에 저장된다.

#### M-04: TODO 항목 삭제

- **User Story**: 사용자로서, 불필요한 항목을 삭제하고 싶다. 리스트를 깔끔하게 유지하기 위해.
- **수용 기준**:
  - 각 항목에 삭제 버튼(아이콘)이 표시된다.
  - 삭제 클릭 시 해당 항목이 즉시 리스트에서 제거된다.
  - 삭제된 항목은 복구되지 않는다 (단순 삭제).

#### M-05: LocalStorage 데이터 영속성

- **User Story**: 사용자로서, 브라우저를 닫았다 열어도 기록이 유지되길 원한다. 다음에도 이어서 사용하기 위해.
- **수용 기준**:
  - 모든 TODO 데이터는 LocalStorage에 자동 저장된다.
  - 페이지 새로고침 후 데이터가 그대로 복원된다.
  - 브라우저를 닫고 재접속해도 데이터가 유지된다.

#### M-06: 기본 TODO 템플릿 제공

- **User Story**: 사용자로서, 처음 앱을 실행했을 때 일본 여행에 맞는 기본 할 일이 미리 입력되어 있으면 좋겠다. 무엇을 준비해야 할지 빠르게 파악하기 위해.
- **수용 기준**:
  - 최초 실행 시(LocalStorage에 데이터 없을 때) 단계별 기본 템플릿이 자동 로드된다.
  - 기본 항목은 사용자가 자유롭게 편집/삭제할 수 있다.
  - 기본 템플릿 내용은 아래 섹션 참조.

### 4.2 Should-have (Phase 2)

#### S-01: TODO 항목 인라인 편집

- **User Story**: 사용자로서, 이미 추가한 항목의 내용을 수정하고 싶다. 오타나 내용 변경이 발생할 때를 위해.
- **수용 기준**:
  - 항목 텍스트 더블클릭 시 인라인 편집 모드로 전환된다.
  - Enter 또는 포커스 아웃 시 저장된다.
  - Escape 키로 편집 취소 가능.

#### S-02: 진행률 표시

- **User Story**: 사용자로서, 각 단계에서 전체 항목 중 몇 개를 완료했는지 보고 싶다. 준비 현황을 한눈에 파악하기 위해.
- **수용 기준**:
  - 각 탭 또는 섹션 상단에 "3/10 완료" 형태로 표시된다.
  - 프로그레스 바(progress bar)로 시각화된다.
  - 완료/추가/삭제 시 즉시 업데이트된다.

#### S-03: 카테고리 분류 (여행 중 모드)

- **User Story**: 사용자로서, 여행 중 할 일을 관광지/맛집/쇼핑 등으로 나눠 관리하고 싶다. 유형별로 빠르게 찾기 위해.
- **수용 기준**:
  - 여행 중 모드에서 카테고리 필터(관광지, 맛집, 쇼핑, 기타)가 표시된다.
  - TODO 추가 시 카테고리를 선택할 수 있다.
  - 카테고리 필터 클릭 시 해당 카테고리 항목만 필터링된다.

#### S-04: 완료 항목 숨기기 토글

- **User Story**: 사용자로서, 완료한 항목을 접어서 미완료 항목에 집중하고 싶다.
- **수용 기준**:
  - "완료 항목 숨기기" 토글 버튼이 제공된다.
  - 토글 ON 시 완료된 항목이 리스트에서 숨겨진다.
  - 토글 OFF 시 전체 항목이 다시 표시된다.

### 4.3 Could-have (Phase 3)

#### C-01: 여행 날짜 설정 및 D-Day 카운터

- 출발일 설정 시 홈 화면에 D-Day 카운터 표시
- "D-3" 처럼 시각적으로 설렘을 유발하는 표시

#### C-02: 항목 드래그 앤 드롭 정렬

- 마우스/터치 드래그로 항목 순서 변경
- 정렬 순서 LocalStorage 저장

#### C-03: 여행 메모 / 짧은 일기

- 여행 후 모드에서 간단한 텍스트 메모 추가
- 날짜별 한 줄 소감 기록

#### C-04: 데이터 초기화 및 새 여행 시작

- "새 여행 시작" 버튼으로 전체 데이터 초기화
- 초기화 전 확인 다이얼로그 표시

#### C-05: PWA 설치 지원

- 모바일 홈 화면에 앱 설치 가능
- 오프라인 접근 지원

### 4.4 Won't-have (이번 버전 제외)

- 사용자 계정 / 로그인 / 클라우드 동기화
- 여러 여행 여정 동시 관리
- 사진 첨부
- 소셜 공유 기능
- 실시간 다기기 동기화
- 지도 연동 / 위치 기반 기능
- 알림(Push Notification) — 단, PWA 확장 시 검토 가능

```
- [ ] 숙소 예약 확인

- [ ] 엔화 환전
- [ ] 해외 결제 가능 카드 확인
- [ ] 트래블월렛 / 트래블로그 충전

[짐 싸기]
- [ ] 여행 가방 꺼내기
- [ ] 의류 준비
- [ ] 세면도구 준비
- [ ] 상비약 챙기기 (소화제, 두통약)
- [ ] 카메라 / 보조배터리 충전

- [ ] 구글 맵 일본 오프라인 지도 다운
- [ ] 구글 번역기 일본어 오프라인 다운
```

```
- [ ] 스이카 충전 확인
- [ ] IC카드 잔액 확인

- [ ] 귀중품 보관 확인

```

```
- [ ] 인스타그램 / 블로그 후기 작성
- [ ] 여행 경비 정산
```

### 7.2 각 단계별 디자인 스펙

#### 여행 전 (Before Trip) — 설레임 테마

| 요소 | 스펙 |
|------|------|
| 배경 컬러 | 따뜻한 파스텔 핑크-오렌지 그라데이션 (#FFF0E6 → #FFE4D6) |
| 액센트 컬러 | 코랄 핑크 (#FF6B6B) |
| 히어로 텍스트 | "두근두근! 일본 여행 준비 중" |
| 서브카피 | "설레는 여행의 시작, 하나씩 체크해봐요" |

### 8.2 전체 데이터 스키마

```typescript
// 최상위 저장 구조
interface JapanTripData {
  version: string;           // 데이터 스키마 버전 (예: "1.0")
  createdAt: string;         // ISO 8601 (최초 생성일)
  updatedAt: string;         // ISO 8601 (마지막 수정일)
  tripInfo: TripInfo;        // 여행 기본 정보 (Phase 2)
  todos: TodosByPhase;       // 단계별 TODO 데이터
}

// 여행 기본 정보 (Phase 2 확장 시 사용)
interface TripInfo {
  title: string;             // 여행 이름 (예: "2026년 오사카 여행")
  departureDate: string | null;  // 출발일 ISO 8601
  returnDate: string | null;     // 귀국일 ISO 8601
}

// 단계별 TODO 묶음
interface TodosByPhase {
  before: TodoItem[];        // 여행 전 TODO 배열
  during: TodoItem[];        // 여행 중 TODO 배열
  after: TodoItem[];         // 여행 후 TODO 배열
}

// TODO 단일 항목
interface TodoItem {
  id: string;                // UUID v4 (예: "a1b2c3d4-...")
  text: string;              // 항목 내용 (최대 200자)
  completed: boolean;        // 완료 여부
  category: TodoCategory;    // 카테고리 (Phase 2)
  createdAt: string;         // ISO 8601
  completedAt: string | null; // 완료 시각 ISO 8601, 미완료 시 null
}

// 카테고리 (여행 중 모드에서 주로 사용, Phase 2)
type TodoCategory =
  | "default"      // 기본 (여행 전/후)
  | "sightseeing"  // 관광지
  | "food"         // 맛집
  | "shopping"     // 쇼핑
  | "transport"    // 교통
  | "accommodation" // 숙소
  | "other";       // 기타

// 현재 활성 단계 (UI 상태 — SessionStorage 또는 useState로 관리)
type TripPhase = "before" | "during" | "after";
```

## 9. 기술 스택 제안

| 구분 | 기술 | 선택 이유 |
|------|------|-----------|
| 프레임워크 | Next.js 14+ (App Router) | 요구사항 명시, SPA로 동작 가능 |
| 언어 | TypeScript | 타입 안전성, 데이터 스키마 명확화 |
| 스타일링 | Tailwind CSS | 빠른 UI 개발, 단계별 테마 적용 용이 |
| 상태 관리 | React useState / useReducer | 외부 라이브러리 없이 충분히 처리 가능 |
| 데이터 영속성 | LocalStorage (browser native) | 백엔드 없음 조건 충족 |
| 아이콘 | Lucide React | 가볍고 일관된 아이콘셋 |
| 고유 ID 생성 | crypto.randomUUID() | 외부 의존성 없음 |
| 배포 | Vercel | Next.js 최적화, 무료 플랜 |

## 11. 리스크 및 고려사항

### 기술적 리스크

| 리스크 | 발생 가능성 | 대응 방안 |
|--------|-----------|----------|
| LocalStorage 용량 초과 | 낮음 (텍스트 데이터 한정) | 항목 개수 상한선 설정 (단계별 최대 100개) |
| 브라우저 시크릿 모드에서 데이터 미저장 | 중간 | 시크릿 모드 감지 시 안내 메시지 표시 |
| iOS Safari의 LocalStorage 제한 | 중간 | sessionStorage 폴백 로직 추가 검토 |
| Next.js SSR과 LocalStorage 충돌 | 높음 | `useEffect` 내부에서만 LocalStorage 접근, `typeof window !== 'undefined'` 가드 처리 |

### UX 리스크

| 리스크 | 내용 | 대응 방안 |
|--------|------|----------|
| 실수로 항목 삭제 | 삭제 후 복구 불가 | Phase 2에서 Undo 토스트 메시지 검토 |
| 모바일 키보드 UI 가림 | 입력창이 키보드에 가려짐 | CSS `env(keyboard-inset-height)` 활용, 입력창 하단 고정 레이아웃 최적화 |
| 기본 템플릿 과다 | 처음 접속 시 너무 많은 항목으로 부담감 | 카테고리 접기/펼치기로 단계적 표시 |
